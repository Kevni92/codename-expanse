# Workflow: Concept Development

## Goal
Produce a coherent, handbook-quality game/system concept.

## Steps
1. Read [`../../AGENTS.md`](../../AGENTS.md), project vision and related concepts.
2. Identify the system's owner document and avoid duplicating rules owned elsewhere.
3. Establish purpose, scope and non-scope.
4. Define terminology.
5. Describe player experience and observable behaviour.
6. Define rules/state transitions/interactions.
7. Add concrete examples and initial parameters where useful.
8. Enumerate edge cases and failure states.
9. Link related concepts using relative Markdown links.
10. List unresolved design decisions under **Open Questions**.
11. Define concept-level acceptance criteria.
12. Use [`../../docs/templates/concept.md`](../../docs/templates/concept.md).
13. Add/update the entry in [`../../docs/concepts/README.md`](../../docs/concepts/README.md).
14. Leave status as `Draft` or `Review` until explicitly approved.

## Completion gate
The concept should read as one chapter of a larger game handbook and be understandable without reading source code.
