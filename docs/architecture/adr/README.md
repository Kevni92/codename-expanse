# Architecture Decision Records

ADRs record durable technical decisions and their consequences.

Use [`../../templates/adr.md`](../../templates/adr.md).

Recommended numbering: `ADR-0001-short-title.md`, incrementing monotonically.

## Accepted ADRs

- [ADR-0001: Browser-First Client-Only Prototype](ADR-0001-browser-first-prototype.md)
- [ADR-0002: Data-Driven Tunable Values](ADR-0002-data-driven-tunable-values.md)
- [ADR-0003: Fast Test Pyramid With Minimal E2E](ADR-0003-fast-test-pyramid.md)
- [ADR-0004: Simulation Is Independent From Rendering and UI](ADR-0004-simulation-rendering-separation.md)
- [ADR-0005: TypeScript Browser Toolchain Baseline](ADR-0005-typescript-browser-toolchain.md)

An ADR should be created when a decision is cross-cutting, difficult to reverse, establishes a project-wide constraint, or deliberately supersedes an earlier architectural rule.
